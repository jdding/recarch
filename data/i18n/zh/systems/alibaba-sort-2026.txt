surface|AliExpress 的 HomePage、DetailPage、ShoppingCart 和 AfterPayment 排序
era_reason|核心主张是 HSTU 一路的可扩展 Transformer 排序模型：统一的 token 序列，用下一个 item 预测的生成式预训练得到 item embedding，并给出数据、模型和序列长度上的扩展曲线，扩展性就是主打卖点。
tldr|阿里国际的 SORT 是以请求为中心组织样本、带生成式预训练的 Transformer 排序模型；在 AliExpress 上订单 +7.47%，GMV +8.65%，延迟 -62%。
summary|SORT 在 AliExpress 上取代了传统 DLRM 排序模型，围绕排序里特征稀疏和标签稀疏两个问题设计。样本以请求为中心：一个样本包含用户历史、用户画像和该请求的全部候选，共享特征只处理一次。输入是一条序列，[BOS; 历史 token; SEP; 画像 token; SEP; 候选 token]，每个 item 由拼接后的特征 embedding 得到一个 token。注意力使用 RoPE、QKNorm 和接在注意力输出之后的门控，用对角 mask 让候选只能看到自己和历史，大部分历史 token 使用局部注意力，并用 query 剪枝在最后一层最多保留 128 个非候选 token。FFN 是 DeepSeek 风格的稀疏 MoE，激活函数为 SwishGLU。排序头预测点击、加购和购买。模型没有用户 ID 特征，item embedding 先用点击序列上的下一个 item 预测做预训练，再迁移并冻结，之后才训练排序模型，这避免了直接迁移时出现的过拟合。训练基于 RecIS 框架，MoE 用 Megablocks，并配有自研的稀疏注意力算子和多进程组通信；推理使用静态图、稀疏注意力 kernel、算子融合、半精度和 KV cache。
core_idea|把 DLRM 排序模型重建为基于单条以请求为中心序列的 Transformer，并用冻结 item embedding 的生成式预训练让它能够稳定训练。

results_reported|四个 AliExpress 场景上为期一个月的线上 A/B，SORT 对比线上 DLRM。宏平均：订单 +7.47%，买家 +6.67%，GMV +8.65%，延迟 -62%，吞吐 +589%。分场景看，订单为 HomePage +2.37%、DetailPage +8.99%、ShoppingCart +7.10%、AfterPayment +11.43%；GMV 为 +10.01%、+11.49%、+6.98%、+6.12%；延迟为 -62%、-51%、-64%、-72%；吞吐为 +325%、+405%、+448%、+1180%。离线方面，base 规模的 CTR AUC：SORT 0.7497，Transformer 0.7456，HSTU 0.7438，OneTrans 0.7476；large 规模 SORT 达到 CTR AUC 0.7536，Transformer 为 0.7485，即 +0.51pt，FLOPs 为 188G 对 322G。采用稀疏迁移加冻结的生成式预训练，使 base Transformer 的 CTR AUC 提升 +2.81pt，而只做迁移则变化 -0.13pt。局部窗口在 64、128、256 中 256 最好。推理优化相比未优化基线带来 29.4% 的吞吐提升和 29.3% 的延迟下降。数据、模型和序列长度的扩展各自都提升 AUC，其中数据扩展斜率最陡。
