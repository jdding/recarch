surface|快手电商商品卡、短视频、直播物品分发场景的端到端生成式检索
era_reason|以业务感知语义 ID 分词器、decoder 风格 Sparse MoE 主干和排序奖励 RL 后训练构成自回归生成式检索；生成式技术栈本身是主角。
tldr|OneMall 用业务感知语义 ID 分词器加 Sparse MoE 解码器与排序奖励 RL 统一快手电商检索；A/B 使 GMV 最高提升 +14.71%，服务超 4 亿日活。
summary|OneMall 是快手面向电商的端到端生成式推荐框架，把商品卡、短视频、直播的物品分发场景统一进一条对齐 LLM 预训练与后训练范式的训练管线。分词器在 QARM 的 Res-Kmeans 基础上加 FSQ 末层，把微调 LLM 产出的物品向量量化成三级语义 ID；商品卡只量化商业向量，短视频拼接商业与观看向量，直播物品因在售商品随时间变化而改用双塔物品塔向量量化，并把实时在售商品语义 ID 作为附加特征。主干用 Query-Former 压缩曝光、点击、购买序列，经 Cross-Attention 融合，再由 decoder 风格 Sparse MoE Transformer 生成语义 ID，线上部署 0.5B 总参数、0.1B 激活。RL 管线把线上排序模型当奖励模型，融合其 CTR、CTCVR、EGPM 打分，用 DPO 与 GRPO 优化检索器。系统已部署，服务超 4 亿日活用户。
core_idea|把物品编码成业务感知的三级语义 ID，用 Sparse MoE 解码器生成候选，再以排序模型奖励经 DPO 与 GRPO 训练检索器。

results_reported|部署：OneMall 服务快手电商商品卡、短视频、直播场景，日活超 4 亿，见摘要与第 1 节。线上 A/B 见表 3 与 4.3 节：商品卡曝光 +2.851%、点击 +13.01%、订单 +8.35%、GMV +14.71%；短视频曝光 +15.32%、点击 +5.76%、订单 +11.65%、GMV +10.33%；直播曝光 +2.78%、点击 +2.53%、订单 +4.47%、GMV +4.90%；摘要将其 GMV 写成 +14.7%、+10.3%、+4.9%。电商短视频场景的离线缩放验证见表 1 与 4.1 节：从 0.05B 到 1.3B-A0.1B，Acc-SID1/2/3 由 14.5%/43.9%/61.0% 升到 16.2%/51.7%/71.7%，HR@50/100/500 由 32.9%/41.3%/60.5% 升到 45.6%/57.3%/76.0%，其中 0.1B 稠密到 0.5B-A0.1B 稀疏的跃迁提升最大，HR@50 提升 10%，即 34.7% 到 44.7%。0.5B-A0.1B 在回放流量上的仿真对比见表 2，各方法输入特征相同：商品卡上 OneMall 达 34.3%/40.9%/59.3%，对 SASRec-0.5B-A0.1B 的 23.2%/30.4%/45.1% 与 TIGER-0.5B-A0.1B 的 29.5%/37.1%/53.7%；短视频上 44.7%/56.0%/74.2%，对 30.2%/41.9%/66.3% 与 35.1%/47.8%/72.5%；直播上 65.9%/69.1%/80.5%，对 53.9%/58.8%/68.4% 与 57.3%/63.5%/73.7%。RL 消融见表 4：在 Top10/100/500 上 GRPO 都好于 DPO 与 Base，如 Top10 CTR 为 GRPO 7.874%、DPO 7.834%、Base 7.816%，GRPO 对 DPO 在 Top10 带来 +0.040% CTR、+0.012% CTCVR、+0.228% GPM。0.3B-A0.1B 上的分词器消融见表 5：ResKmeansFSQ 把码冲突从 36% 降到 11%，独占码从 86% 升到 95%；辅助对比损失在 HR@50/100/500 上再加 +1.5%/+1.7%/+1.7%。Query-Former 消融见表 6：压到 SeqLen 160、每样本 9.2 GFLOPs 时，命中率只比 SeqLen 1205、34.4 GFLOPs 的版本差 +0.5%/+0.3%/+0.4%。批内对比任务 accuracy@1 超 98%，故线上推理只用 beam search，见 3.2 节。
serving_infra|服务商品卡、短视频、直播场景的候选生成；线上推理只跑 beam search，因对比任务 accuracy@1 超 98%。论文以线上服务算力受限为由把激活参数上限压到 0.1B；延迟、吞吐与硬件数字均未给出。
stages.0.model_family|Decoder 风格 Sparse MoE Transformer，配 Query-Former 序列压缩、Cross-Attention 多行为融合与因果自注意力；线上部署 OneMall-0.5B-A0.1B，12 个专家取 2 个，beam search 解码三级语义 ID
stages.0.details|Query-Former 按行为各压一条序列，查询 token 数约 10、输入长度约 500、维度约 128；Cross-Attention 把压缩后的兴趣融进语义 ID 查询状态；Sparse MoE 解码器用 loss-free 机制做专家负载均衡，0.5B-A0.1B 配 12/2 专家、1.3B-A0.1B 配 24/2 专家
id_tokenization.approach|三级语义 ID：两层 Res-Kmeans 加一层 16 比特 FSQ、末层 4096 码，量化对象是 LLM 对齐的物品向量，沿 QARM 的 Res-Kmeans 扩展成 ResKmeansFSQ
id_tokenization.details|物品向量来自用商业 Item2Item 语料与观看 Item2Item 语料做 InfoNCE 对比微调的 LLM，视觉编码用 Swin-Transformer、文本编码用 Qwen2.5 1.5B，ViT 冻结。商业语料抽样时单物品出现不超过 40 次，共 7000 万样本；观看语料共 1200 万样本。商品卡只量化商品向量；短视频拼接商品与视频向量；直播物品量化双塔物品塔向量，实时在售商品语义 ID 作附加特征，物品塔用更低学习率。表 5 显示 ResKmeansFSQ 把码冲突从 36% 降到 11%

features_signals.2|分词器的多模态输入：商品主图 224*224 加标题；短视频抽 6 帧画面 224*224 加标题、OCR 与 ASR
features_signals.3|直播物品的实时在售商品语义 ID 附加特征
features_signals.4|排序模型输出的 CTR、CTCVR、EGPM 融合成 RL 奖励
