summary|SARM 把直播间的自然语言描述直接放进排序模型，而不是使用离散 Semantic ID 或另行提取的稠密多模态 embedding。微调过的多模态 LLM 读取主播资料、关键帧、音频转写和评论，为直播间写出六个语义锚点：POI、Theme、Topic、Target audience、Format 和 Scene。锚点成为可学习的文本 token。四个 block 的 Semantic Anchor Encoder 加上 Live-Streaming Tokenizer 对它们编码，每一层之后都用门控融合把新增的领域 token 与基础 token 序列混合。它输出 [CLS] 语义表示；由主播 ID embedding 与语义输出做 cross-attention 得到的 [TAR] 主播表示；以及 [UIN] 用户兴趣表示，由 self-attention Transformer 在用户有效观看历史中各主播的 [CLS] 向量上构建。这三种表示与基础排序模型的现有特征拼接，基础模型是线上的 HoME MMoE 多任务模型，预测点击、关注、长播和打赏目标。作用在 [CLS] 和 [TAR] 上的辅助 CTR 损失给语义编码器提供稠密监督并加快收敛。部署是围绕按主播 ID 索引的 memory bank 做的非对称设计：LLM 每天为每位主播生成一次锚点，编码器和排序模型以流式方式训练，推理时召回返回的候选主播通过常数时间的查表取得向量，所以每个请求都不运行 LLM 或文本编码。用户侧在训练和服务中的做法相同。
core_idea|让离线多模态 LLM 为每个直播间写文字锚点，并在排序模型内端到端训练其编码器，再用 memory bank 保证每个请求都不用运行重计算。

results_reported|离线，以线上的 HoME 为基础排序模型，SARM 把 CTR 的 AUC 和 GAUC 从 0.8387 和 0.6453 提高到 0.8411 和 0.6485，LVTR 的 AUC 和 GAUC 从 0.8928 和 0.7542 提高到 0.8959 和 0.7580。使用标签、SID 或 MMBee 与 SIM 的 MLLM embedding 的两阶段基线，CTR AUC 分别为 0.8390、0.8389、0.8385 和 0.8394。每一层之后做门控融合是最好的融合方式，分层分析显示低曝光主播的相对收益更大。把 Qwen2.5-VL-7B 锚点换成 Qwen3-VL-8B，相对基础模型的 CTR AUC 提升从 +0.19% 增加到 +0.24%。关键页面上为期两周的线上 A/B：快手的 Exposure +0.424%，Watch Count +0.189%，Watch Time +0.092%，Click +0.982%，Gift +0.482%，Effective View +0.070%，Follow +0.805%；快手极速版的 Exposure +1.190%，Watch Count +0.397%，Watch Time +0.962%，Click +0.562%，Gift +1.287%，Effective View +0.340%，Follow +0.522%。Table 5 中训练 CPU 利用率为 51.71%，基础模型为 48.69%；GPU 为 80.29%，基础模型为 77.54%；每轮训练时间为 1.08x；推理 QPS 为 271.30，基础模型为 280.71；每次查询时间为 1.02x，论文没有报告统计显著的退化。
