era_reason|自回归地生成以期望结果为条件的 item embedding 序列，每个生成的 embedding 都用于近邻召回，生成处于召回的核心位置。
tldr|Pinterest 的 PinRec 是跨场景预训练、再按场景微调的统一生成式召回模型，带结果条件生成；Search A/B 中 fulfillment +2.24%，saves +3.88%。
summary|PinRec 是 Pinterest 的候选生成器，部署在 Home Feed、Related Pins 和 Search 三个场景。一个 12 层 transformer decoder 读取由 Pin 和搜索 query 组成的用户序列，每个元素由预训练的 OmniSage 和 OmniSearchSage 向量加上时间和场景 embedding 得到。它先在跨所有场景的终身行为序列上做下一个 item 预测的预训练，使用 sampled softmax，负样本为 batch 内负样本，并用 count-min-sketch 做偏差校正。然后在每个场景自己的 feed 浏览日志上微调，场景内的行为作为额外正样本，只有曝光的 item 作为 hard negative。结果条件生成在输出头上加入可学习的结果 embedding，一次前向就能为每种结果，例如保存或外链点击，各产出一个 embedding，召回预算按结果切分，以此权衡业务指标。生成是自回归的：每一步把采样出的 embedding 连同时间偏移追加回序列，相似的 embedding 按 cosine 相似度合并，每个 embedding 各做一次 Faiss IVF-HNSW 近邻查询。模型部署在 NVIDIA L40S GPU 上，经 Triton 提供服务，使用 CUDA graphs 和 KV cache；候选原样进入已有的排序和混排阶段。
core_idea|预训练一个跨所有场景的生成式召回模型，按场景微调，并让生成以各场景关心的结果为条件。

results_reported|作为候选生成器的线上 A/B，候选原样进入排序和混排。Search 上，PinRec-OC 对比 control group：search fulfillment rate +2.24%，search saves +3.88%，search shares +5.30%。Home Feed 上，OC 对比 UC：fulfilled sessions +0.21% 对 +0.02%，site-wide grid clicks +1.76% 对 +0.58%，Home Feed grid clicks +4.01% 对 +1.87%。Related Pins 上，OC：fulfilled sessions +0.21%，time spent +0.38%，site-wide grid clicks +0.76%，sitewide saves +0.26%，同时 Search 的 fulfillment +0.42%，saves +0.39%。零样本方面，Related Searches 的 fulfilled sessions +1.66%，module click rate +4.04%，Ads 的 cost per acquisition -1.83%，cost per click -1.41%。对比线上的生产双塔模型，corpus coverage OC 为 +17.3%，UC 为 +6.2%。离线 unordered recall at 10，依次为 Home Feed、Related Pins、Search：SASRec 0.382、0.426、0.142；PinnerFormer 0.461、0.412、0.257；TIGER 0.208、0.230、0.090；HSTU 0.596、0.539、0.179；PinRec-UC 0.608、0.521、0.350；PinRec-OC 0.625、0.537、0.352。去掉结果条件，recall 下降 -7.5% 到 -12.6%；去掉微调，下降 -2.0% 到 -4.5%。与 1 步相比，16 步自回归生成使 recall 在 Related Pins 上提升 +71.4%，Home Feed 上 +8.8%，Search 上 +11.1%。服务延迟在 p50 上是双塔模型的 3-4x，端到端只增加不到 1%。

serving_infra|NVIDIA L40S GPU 加 Triton ensemble 和 Python backend；分为取信号、Pin 特征化、自回归推理和 Faiss 召回几个阶段。CUDA Graphs 加 torch.compile 和按请求缓存的 KV cache 降低开销。序列 embedding 以 INT8 传输，推理时反量化为 FP16。
stages.0.model_family|Transformer decoder，12 层、12 个 head、768 隐层维度，约 1 亿参数，自回归地生成连续的 item embedding，输出头带结果条件
stages.0.details|embedding 由 CPU 主机上的 Faiss IVF-HNSW 以内积匹配到 Pin，并有 overfetch 系数用于之后去重。召回预算按每个生成的 embedding 切分：无条件时平均分，有条件时按结果预算分。cosine 相似度超过阈值的 embedding 会被合并，预算相加。
id_tokenization.approach|没有；使用稠密 embedding，不用 Semantic ID
id_tokenization.details|Pin 使用预训练的 OmniSage embedding，query 使用 OmniSearchSage，各自经过 2-3 层全连接并做 L2 归一化，再加上绝对和相对时间 embedding 以及场景 embedding。作者试过 Semantic ID，发现在 Pinterest 规模下有数万个 item 碰撞到同一个 ID，指标也更低，于是选用稠密 embedding，它同时不会幻觉出不存在的 item。
